SmartInventory

Gestión y control de inventarios con persistencia NoSQL políglota

MongoDB Redis Neo4j Prometheus React + Node.js

Problema y objetivo

Un inventario que nunca se descuadra

1

Control de existencias

Entradas, salidas y ajustes. El stock solo cambia mediante movimientos y nunca queda en negativo.

2

Alertas automáticas

Cada producto se clasifica como normal, con stock bajo o agotado según su mínimo.

3

Acceso por roles

Administrador y almacenero, con sesión por token JWT y contraseñas cifradas con bcrypt.

Regla de negocio central

Un movimiento: todo o nada

ValidarLa salida no puede superar el stock disponible
→
TransacciónActualiza el stock y guarda el movimiento juntos
→
CachéBorra el resumen guardado del dashboard
→
MétricaCuenta el movimiento como exitoso o fallido
AGOTADOEl stock llegó a cero
STOCK_BAJOEl stock es menor o igual al mínimo
NORMALEl stock está por encima del mínimo

Redis y Neo4j

Velocidad en la lectura, relaciones en el grafo

Redis · caché del dashboard
  • Si el resumen está en caché, se responde desde ahí.
  • Si no, se calcula en MongoDB y se guarda 60 segundos.
  • Cada movimiento o cambio de producto borra la clave.
cache:dashboard_resumen
Neo4j · grafo de suministro
  • Al crear un producto se sincroniza su nodo.
  • Permite preguntar qué provee cada proveedor.
(:Proveedor)-[:SUMINISTRA]->(:Producto)
(:Producto)-[:PERTENECE_A]->(:Categoria)
